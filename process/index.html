Process

How we work

We build tools that we use every day in our own games. This page tells you how a tool goes from an idea to a release, and which tools we use to make it.

From idea to release

Each step must be complete before the next step starts.

  1. Write the idea down

    Each idea goes on our planning board. Ideas that we plan to build, ideas that we parked, and ideas that we rejected go on the public roadmap, each with a reason.

  2. Ask the game first

    If we do not know how the game stores something, we do not guess. We build a small test plugin that reads the value from the game and reports it. Only facts that we confirmed go into a released tool.

  3. Use the game's own data

    Our plugins read quests, items and places from the game's own data tables. When the game does not hold a fact, we use the community wiki, and we show where the fact comes from.

  4. Test in the game

    A change is complete only when it works in the game. "It builds" is not enough. We test each change on our own characters before we release it.

  5. Release in public

    All source code is on GitHub. An automatic build makes each plugin release from that code, so the download is the same as the source that you can read.

What our tools do not do

Some rules apply to every tool that we make. We do not change these rules to add a feature.

  • Our plugins do not automate the game. They do not press keys or send commands for you.
  • Our plugins do not read combat logs or damage numbers.
  • Our tools describe your progress. They do not rank you or call your progress good or bad.
  • Our web apps keep your data in your browser. There is no account and no server that holds your data.
